# Unison 系统架构图

## 一、四层架构（后端）
main → scope → core → repos → types

| 层 | 职责 |
|---|---|
| types | 数据行类型、帧语义类型、DTO、统一响应结构、配置模型 |
| repos | SQLite 连接、建表索引、SQL 与行映射、模型流式客户端、SSE 连接池 |
| core | 版本裁决、生成调度、打断边界、确认落库、任务接管、身份生命周期 |
| scope | 参数校验、身份解析、响应包装、REST 路由与 SSE 端点 |
| main | 应用装配入口 |

## 二、前端分层
pages（15 页面）→ common（components / api / stores / router / utils）→ lib（$lib/components/ui，禁改）

## 三、数据流
端 → REST 上行 → scope → core → repos → SQLite
端 ← SSE 下行 ← stream_hub ← stream_chunks（30—50ms 合批）

## 四、四轨道
| 轨道 | 范围 | 承担者 |
|---|---|---|
| S 服务端 | M1—M10 | B1 / B2 / B3 |
| F 前端 | M11—M18 | F1 / F2 / F3 |
| D 横向 | M0、M19、M20 | N1 / N2（脚本归 B3） |
| C 守门 | 契约、配置、集成 | B1 |

## 五、两条铁律
- 版本归服务端单写者；端时钟不参与定序
- draft 临时层与 history 正式层严格分离
