
# Unison 核心时序图

本文件描述系统最关键的多端协同链路：提问、流式广播与中途打断。

## 一次提问与打断的完整时序

下图展示了端 A 发起提问，端 B 中途打断时，各个角色的交互顺序。

```mermaid
sequenceDiagram
    participant F1 as 端 A (前端)
    participant F2 as 端 B (前端)
    participant S as 服务端 (core)
    participant DB as SQLite
    participant API as 大模型 API

    F1->>S: POST /questions (generationId, baseVersion)
    S->>DB: 写入 generation_tasks (in_progress)
    S->>API: 发起模型流式调用
    S-->>F1: 200 受理成功
    S-->>F2: 200 受理成功 (通过SSE广播)
    
    loop 逐字流式返回
        API-->>S: chunk 数据
        S->>DB: 写 stream_chunks (合批)
        S-->>F1: SSE delta 帧
        S-->>F2: SSE delta 帧
    end
    
    F2->>S: POST /interrupt (generationId)
    S->>DB: 丢弃 draft，计算统一边界
    S-->>F1: SSE interrupt 帧 (带 boundary)
    S-->>F2: SSE interrupt 帧 (带 boundary)
    Note over F1,F2: 四屏停在同一 boundary，清空 draft

    opt 如果不打断，正常结束
        S->>DB: 分配新版本，写入 records & version_log
        S-->>F1: SSE confirm 帧
        S-->>F2: SSE confirm 帧
    end
