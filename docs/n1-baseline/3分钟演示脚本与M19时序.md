# Unison 3 分钟演示脚本与 M19 时序

## 一、演示准备（演示前 1 分钟）

1. 确认 4 台设备（如笔记本、平板、手机）已连上同一局域网。
2. 确认服务端已通过 `scripts/start_all.py` 一键启动 2—3 个实例。
3. 4 台设备分别打开 `LandingPage`，确认右上角状态角标的实例号各不相同。
4. 准备一台设备放在投屏上，但提示评委：“系统状态不用看投屏，低头看任意一台设备的角标就能读出来。”

## 二、3 分钟八拍脚本

### 第一拍：进房看角标
- **动作**：设备 A 创建房间（显示二维码）。设备 B、C、D 扫码或输入房间号加入。
- **现场话术**：“现在四端进房。请大家看右下角的角标，在线端数从 1 变到了 4。四块屏幕的版本号全部是 0，完全同步。”
- **观察点**：角标“在线端数”显示 4，“同步滞后”为 0。

### 第二拍：提问四屏逐字
- **动作**：设备 A 在 `AskPage` 输入问题：“请用一句话解释服务端版本裁决。”点击发送。
- **现场话术**：“设备 A 发起了提问。此时四块屏幕会同步出现打字机效果，注意看，四块屏幕的首字延迟肉眼几乎不可辨，因为它们接收的是同一批服务端的合批帧。”
- **观察点**：四端同时出现逐字内容；角标“版本”暂时不变（因为是 `delta` 帧）。

### 第三拍：中途插话，统一截断
- **动作**：在逐字还没结束时，设备 B 点击“打断”按钮。
- **现场话术**：“设备 B 觉得回答够了，点击打断。四块屏幕瞬间同时停在同一个字上。打断是由服务端计算统一截断边界，不是各端自己停的，且这次被打断的问答不会产生正式记录。”
- **观察点**：四端逐字立刻停止，临时草稿被清空。

### 第四拍：两端并发共改
- **动作**：设备 A 和设备 B 同时在 `HistoryPage` 编辑同一条正式记录，并几乎同时点保存。
- **现场话术**：“现在 A 和 B 同时修改同一句话。前端不写合并算法，全靠服务端做版本裁决。一个会成功，另一个会收到 409 版本冲突，然后按服务端下发的快照自动回滚重放。”
- **观察点**：两端最终收敛到同一句话，版本号连续递增，无跳号。

### 第五拍：跨端接力
- **动作**：设备 C 对刚才 A 和 B 修改的记录进行追问。
- **现场话术**：“设备 C 接着修改后的上下文继续追问。它从正式记录里拉取快照，上下文完全连续。”
- **观察点**：设备 C 的提问基于最新版本。

### 第六拍：飞行模式 5—10 秒
- **动作**：设备 D 开启飞行模式（断网），在界面上继续操作（修改记录或提问）。5—10 秒后，关闭飞行模式。
- **现场话术**：“设备 D 断网了，角标变红。此时它的操作进入离线队列（Outbox），没有丢失。网络恢复后，它先拉快照，再按版本补拉缺失帧，最后按序补发，版本瞬间追平，不重不漏。”
- **观察点**：设备 D 角标变红再变绿；断网期间的动作在恢复后成功同步到其他端。

### 第七拍：停一个实例
- **动作**：在控制台执行 `stop-instance` 故障注入，停掉设备 A 所连的实例。
- **现场话术**：“我们现场停掉设备 A 所连的实例。大家看，只有设备 A 的角标换了实例号，其他三端全程无感。设备 A 自动重连，历史一条没丢。”
- **观察点**：只有设备 A 的角标实例号变化，其余三端无感。

### 第八拍：断 API 切模拟流
- **动作**：切到 `mock` 流模式，并让设备 A 再次提问。
- **现场话术**：“现在拔掉公网网线，大模型 API 不可用。我们切换到模拟流，零 API 消耗，再次提问，系统依然完整走完生成、确认、落库流程。这就是我们的降级方案。”
- **观察点**：角标显示降级提示，问答依然成功落库。

## 三、M19 编排时序定义

M19 模块负责“一键启动与演示编排”。现场控制台（如 `DemoScriptPage`）按以下时序向服务端发送控制指令：

| 拍数 | 触发动作 | 对应接口/脚本 | 目标模块 | 预期现象 |
|---|---|---|---|---|
| 1 | 4 端进房 | `POST /api/rooms/join` | M1 | 在线端数变为 4 |
| 2 | A 发问 | `POST /api/rooms/:id/questions` | M6 M7 | 四屏同步逐字 |
| 3 | B 打断 | `POST /api/rooms/:id/interrupt` | M8 | 四屏停在同一个字 |
| 4 | A、B 并发编辑 | `POST /api/rooms/:id/edits` | M9 M16 | 收敛同一结果，版本递增 |
| 5 | C 接力提问 | `POST /api/rooms/:id/questions` | M6 M7 | 上下文连续 |
| 6 | D 断网恢复 | 端侧控制 | M14 | 补齐、不重、版本追平 |
| 7 | 停实例 | `POST /api/faults/stop-instance` | M4 | 端换实例号，历史不丢 |
| 8 | 切模拟流 | `POST /api/demo/stream-mode` | M10 | 零 API 消耗，问答落库 |
